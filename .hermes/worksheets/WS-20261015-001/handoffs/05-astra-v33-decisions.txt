仓库读取受环境限制；以下基于你给出的语义，GATE 实现尚未核实。

**1．改名。** 用「时间轴」。同时：claim/release→领取/释放，lease→领取有效期，checkpoint→检查点，artifact→产物，GATE→执行开关；HERMES 徽标补「自动执行中/已暂停」，不能仅表明身份。

**2．时长按执行段累计。** 每段从 claim 到 release；过期按到期时刻封口，重新领取另算，历史缺失标未知。这是“领取占用时长”，不是 CPU 工时。审批、排队、暂停分别计时，不能全部叫等待。

任务条显示「执行 2h15m」，窄条移入悬停卡；卡内显示「执行／待审批／排队／暂停／总历时」。项目显示“累计任务执行时长”；并行段求和，不能冒充项目历时。

**3．项目卡展示证据，不制造工作量。**

- 「活动事件」按去重后的结构化检查点分类：设计、测试、编码、未分类；显示数量、占比、统计范围。任务类型和已批准阶段仅提供默认标签；计划数量不算已发生事件，日志条数不算事件，占比不代表工时或完成度。
- 「代码变更」用 gitstatus 展示相对明确基线的增删行、文件数；未跟踪、二进制另列，生成文件标注。提交数只作辅助；无 Git 显示不可用，不叫产出评分。
- 「需处理」列失败、冲突、心跳失联、待审批超过可配置阈值，附来源、持续时间、处理按钮。等待不等于阻塞；仅明确阻断后续步骤才叫卡点，缺证据显示未知。
- 状态墙分组标题和时间轴项目名打开同一详情抽屉，顶部放项目卡及控制按钮。

**4．接管模式与任务状态分开；转换全部由 server 执行并留审计。**

|状态|触发|动作|谁能触发|
|---|---|---|---|
|人工|开启接管|校验已批准范围→自动|用户|
|自动|步骤完成、心跳正常、验收通过、无越界|领取已批准的下一步；无验收规则不算绿灯|server|
|自动|同一步验收连续失败2次、失联、越界、高危请求|→暂停中，关执行入口、通知|server；Hermes可请求|
|暂停中|受管进程确认停稳|释放领取→已暂停|server|
|已暂停|恢复|复核原因、权限、进程；任务回ready再claim|用户|
|任意|停止接管|项目关入口、撤销旧执行令牌、停止受管进程；停稳→人工|用户|

普通失败暂停该任务及依赖任务；共享目录冲突、权限越界暂停项目。偏离只查批准的路径、工具、步骤、预算，语义偏离只能提示复核。

暂停先挡新步骤，在途请求安全停止，超时中断受管进程；未确认停稳持续显示「停止中」。恢复从已持久化安全检查点续跑；无检查点或副作用不明时由用户选重跑，禁止盲重试。

GATE 应统一控制派单与执行入口；高危始终逐次人工批准，Hermes 无权自批扩权。

明确不做：用命令指纹充当安全边界、声称能拦截任意 tmux 操作。无法受管的终端不开放自动接管。

## English

This release adds the foundation for a project control layer on top of the terminal workspace: automated runbook execution, agent-neutral integration, and terminal notification monitoring.

Highlights:

- **Auto-progression engine** — when a tool run passes, the runbook automatically advances to the next phase and starts the matching tool, chaining through phases without manual clicks
- **One-click orchestration** — `Start Execution` launches the entire runbook; a single action can drive plan → implement → test → review
- **Agent adapter API** — any terminal-first agent (Claude Code, Codex, OpenCode, etc.) can get tasks, submit evidence, and request human review via HTTP API with bearer token auth
- **Terminal notifications** — OSC 9/99/777 escape sequences are parsed from terminal output, pushed via WebSocket, and displayed as badges on workspace tabs with browser notification support
- **Extensible tool registry** — register custom tools (npm test, cargo test, pytest) with per-tool timeout, output limits, and phase restrictions via API
- **Tool CRUD API** — `POST/PUT/DELETE /api/project-control/tools` for managing custom tools

Operational notes:

- after upgrading, rebuild the `roambench` binary and restart the service because front-end assets are embedded in the Go binary
- public downloadable assets are published under `v0.4.1`

Short release blurb:

`RoamBench v0.4.0 is a self-hosted tmux-backed web workbench for long-running terminal and AI coding sessions. This release adds automated runbook execution, an agent-neutral HTTP API, terminal notification monitoring, and an extensible tool registry for the project control layer.`

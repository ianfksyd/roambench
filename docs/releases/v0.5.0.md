# RoamBench v0.5.0

RoamBench v0.5.0 makes long-running terminal and agent workloads safer to leave unattended. It adds per-terminal resource controls, durable phone-friendly interaction handling, and clearer memory-pressure reporting while keeping the existing tmux-backed workflow.

## Highlights

### Resource guards for terminal workloads

- Reject new terminal requests when configured available-memory, swap-use, or cgroup PSI thresholds show sustained pressure.
- Place each new terminal in its own cgroup v2 subtree with optional memory, swap, PID, CPU, and I/O controls.
- Bound the complete RoamBench task pool through the supplied systemd units.
- Show host and service-cgroup memory pressure in the browser header.

### Durable agent decisions

- Store interactions, responses, decisions, audit events, outbox events, idempotency records, and task projections in SQLite.
- Let an agent create a structured request and retrieve the answer after it is handled in another authenticated browser.
- Preserve answers and idempotent retries across service restarts.
- Expire overdue requests and cancel pending requests when their terminal session ends.
- Migrate legacy checkpoint and decision state automatically while retaining a read-only pre-migration backup.

### Terminal and file-workspace improvements

- Stabilize terminal attachment and workspace assignment across multiple browser windows.
- Preview audio and video files directly in the built-in viewer.

### Security and toolchain

- Build the official Linux artifacts with Go 1.27.0.
- Update `github.com/gorilla/websocket` to 1.5.3, fixing GO-2026-6278.
- Scan both source call chains and release binaries with `govulncheck` before publication.

## Upgrade notes

- Front-end assets are embedded in the binary, so replace the binary and restart RoamBench to load the new UI.
- Review the new `[terminal.resources]` settings before enabling per-terminal limits. The example values target a host with about 16 GiB RAM.
- Per-terminal controls require cgroup v2 and a systemd unit with `Delegate=cpu io memory pids` and `DelegateSubgroup=supervisor`.
- The supplied service template also limits the complete RoamBench task pool; tune its percentage-based limits for the host.
- Legacy approvals are migrated on startup. Keep the generated `.pre-control-plane-v1.bak` file until the upgraded service has been verified.

## Install

Linux `amd64` and `arm64` archives, with matching SHA-256 files, are attached to the GitHub Release.

```bash
curl -fsSL https://raw.githubusercontent.com/ianfksyd/roambench/main/scripts/install-roambench.sh | bash -s -- v0.5.0 "$HOME/.local/bin"
```

Trusted local/LAN quickstart after installation:

```bash
APP_BIN="$HOME/.local/bin/roambench"
curl -fsSLo roambench.toml https://raw.githubusercontent.com/ianfksyd/roambench/v0.5.0/configs/roambench.quickstart.toml
"$APP_BIN" --password-hash
export ROAMBENCH_USER="$(whoami)"
export ROAMBENCH_PASSWORD_HASH='<paste the generated hash>'
"$APP_BIN" --config roambench.toml
```

The quickstart configuration enables insecure HTTP and disables IP filtering. Use it only on a trusted local network. For an Internet-facing deployment, start with `roambench.example.toml` and follow the deployment-hardening guide.

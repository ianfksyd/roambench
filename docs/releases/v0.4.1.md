## English

RoamBench is a small self-hosted web workbench for long-running terminal and AI coding sessions. It sits between SSH and a full browser IDE: persistent `tmux` terminals, `1 / 2 / 4` pane workspaces, lightweight file tools, and a browser UI you can reopen from another laptop or phone.

It is built for developers who run Codex, Claude Code, OpenCode, Kimi-CLI, or ordinary scripts on a remote machine and want to supervise them without keeping one laptop open all day.

Trusted local/LAN quickstart after install:

```bash
APP_BIN="$HOME/.local/bin/roambench"
curl -fsSLo roambench.toml https://raw.githubusercontent.com/ianfksyd/roambench/v0.4.1/configs/roambench.quickstart.toml
"$APP_BIN" --password-hash
export ROAMBENCH_USER="$(whoami)"
export ROAMBENCH_PASSWORD_HASH='<paste the generated hash>'
"$APP_BIN" --config roambench.toml
```

The quickstart config enables insecure HTTP and disables IP filtering, so use it only on a trusted local or LAN environment. For anything exposed beyond that, start from `roambench.example.toml` and read the deployment hardening docs.

## What Changed In v0.4.1

This release expands the project control layer on top of the terminal workspace: automated runbook execution, agent-neutral integration, terminal notification monitoring, failure recovery, and visibility into active agent/tool work.

Highlights:

- **Auto-progression engine** - tool pass -> auto-advance phase -> continue through the runbook without manual clicks
- **One-click orchestration** - `Start Execution` launches the runbook automatically
- **Agent adapter API** - terminal-first agents can get tasks, submit evidence, and request human review over HTTP
- **Agent CLI** - `roambench-agent` standalone binary for hook integration
- **Agent-as-tool support** - define tools with `kind: agent` that wait for an external callback
- **Terminal notifications** - OSC 9/99/777 messages are parsed from terminal output, pushed over WebSocket, and shown as tab badges
- **Extensible tool registry** - register custom tools such as `npm test`, `cargo test`, or `pytest` through the API and UI
- **Failure recovery** - auto-retry on transient errors and checkpoint when retries are exhausted
- **Health monitor** - phase timeout and stall detection, including agent tool run timeout watchdogs
- **Scheduled execution** - periodic tool runs on active task phases
- **Dashboard agent activity** - global view of running and waiting tool runs

Operational notes:

- Rebuild the binary and restart the service when building from source, because front-end assets are embedded.
- `make release-packages TAG=v0.4.1` produces the Linux release artifacts.
- `make build-agent` builds the `roambench-agent` CLI separately.
